Some problems don't get easier when you add engineers. If correctness, performance or
physics has already ruled out the obvious approach, a bigger team just reaches the same
wall sooner. Those are the problems we take, and we take them from defining the problem
to code your team runs without us.

### What we work with

- **HPC and heterogeneous compute**: GPU workloads and multi-node performance, including clusters where the devices no longer match each other.
- **Formal verification and microkernels**: minimal trusted bases and provable isolation. We are an seL4 tech partner.
- **Agentic systems**: autonomous control loops for hardware, toolchains and regulated domains.
- **Optimised compute pipelines**: custom backends, optimisation pipelines and compiler passes.
- **On-prem deployment and maintenance**: ML models served inside air-gapped environments, and kept running there.
- **Custom tooling**: instrumentation and toolchains built to fit the problem, including Triton kernels and custom network protocols.

We build the product layer on top of that too: apps, developer infrastructure and SDK
tooling, and the product strategy for deciding what to build first.

### How we work

Scope → build → verify → handover. Every phase puts something in your hands before the
next one starts: a written problem statement, a running build at each milestone,
benchmarks you can rerun yourself, and a repo your team runs without us.

You own all deliverables and their rights. Pre-existing and general-purpose tooling stays
ours, and where it is useful to anyone else we publish it here.
